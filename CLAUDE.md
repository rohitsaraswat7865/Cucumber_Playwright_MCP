# CLAUDE.md — Playwright + Cucumber BDD test framework

> **How to read this file.** Every section states **when it applies**, **what to do**, and **why**.
> Sections marked 🚫 STOP are preconditions, not advice: they gate an action rather than describe it.
> Where a section's rule and your own judgment disagree, the section wins.

## 1. Overview

Playwright test runner + Gherkin scenarios, glued. ESM (`"type": "module"`), Chromium only, headed by default.

| Path | Role | Editable |
|---|---|---|
| [features/](features/) `**/*.feature` | Gherkin scenarios in business language | ✅ |
| [steps/test.steps.js](steps/test.steps.js) | Step definitions via `createBdd()` | ✅ |
| [playwright.config.js](playwright.config.js) | `defineBddConfig({ features, steps })` + runner config | ✅ |
| [global-setup.js](global-setup.js) | One-time login → writes both `.auth/` artifacts (§5) | ✅ |
| [session-state.js](session-state.js) | Format contract for the session file: read/write/validate, shared by both consumers | ✅ |
| `.auth/session.json` | Captured session state — required shape in §5 | ❌ generated |
| `.auth/session.init.js` | Web-storage init script the MCP server loads via `--init-script` | ❌ generated |
| `.features-gen/` `test-results/` `playwright-report/` `blob-report/` `node_modules/` | Build/report output | ❌ generated |

**Never hand-edit anything in an ❌ row (N4).** `.features-gen/` in particular is regenerated by `bddgen` on every run, so edits there are silently discarded the moment the user runs the suite.

## 2. 🚫 STOP — Claude does not run the test suite

**Applies when:** you are about to run any command that executes the suite, regenerates specs, or performs the login. Concretely — including but not limited to — `npx playwright test`, `npm test`, any `npm run` script wrapping them, `bddgen` / `npx bddgen`, and `node global-setup.js`.

**Rule:** do not run them. Running the suite triggers the real login flow, so starting it is the user's decision, not yours.

**Instead, hand off.** Stop where you are and tell the user:

1. what you completed,
2. what is blocked, and the exact command that unblocks it,
3. what stays unverified until that command runs.

Then wait.

**Do not** route around the block by verifying against a logged-out page, and **do not** describe a step as passing, working, or done on the assumption that it would pass (N5).

## 3. 🚫 STOP — gate: both `.auth/` artifacts must exist and be well-formed before any MCP browser call

**Applies when:** you are about to call *any* `mcp__playwright__browser_*` tool — any tool, any page, any reason.

**Procedure**

1. Read `.auth/session.json` and confirm **every** condition:
   - [ ] the file exists and parses as JSON;
   - [ ] `origins` is present and is an **array** (plural key, array value);
   - [ ] `cookies` is present;
   - [ ] `sessionStorage` is present;
   - [ ] `.auth/session.init.js` also exists — without it the MCP browser gets no web storage.

   Exact shape in §5.
2. **All pass** → proceed to §4.
3. **Any fail** → stop and report it as a blocking error. Call no browser tool. Do not create, repair, or hand-write either artifact yourself — regenerating them means logging in (§2). Tell the user which check failed and that they need to run global setup to regenerate both `.auth/` artifacts, then ask you to retry.

**Why existence alone is not enough.** A hand-written file with a singular `origin` key and an object-shaped `localStorage` — the natural shape to write by hand — parses without error, because Playwright silently ignores keys it doesn't recognize. `--storage-state` **fails silently** on a missing or non-native file: you get a logged-out browser and no error message. Every selector, role, name, and title you then verify will be wrong for real authenticated scenarios — and wrong in a way that looks confidently correct.

**Do not skip this gate** because the task seems simple, because the page probably doesn't need auth, or because you are only taking a quick look. Re-run it at the start of each browsing session — sessions expire and are never auto-refreshed (§5).

## 4. Workflow — writing or changing a step definition

**Applies when:** adding or editing anything in [steps/](steps/).

**Core constraint (N3):** never write a locator, role, accessible name, URL, or title assertion from memory, from the feature file's wording, or from what the page "should" look like. Confirm each one against the live page first.

**Why:** a locator that merely looks plausible still parses and still runs — it just fails, or worse silently matches the wrong element, the first time the real page differs from your assumption. The cost of skipping verification stays invisible until the user runs the suite, which is exactly when you are no longer there to catch it.

**Procedure**

1. Run the §3 gate.
2. **Load the tools.** `mcp__playwright__*` tools are deferred — listed by name only until their schemas are fetched, and not callable until then. Call the `ToolSearch` tool (this is a tool call, not a shell command) with the query:
   `select:mcp__playwright__browser_navigate,mcp__playwright__browser_snapshot,mcp__playwright__browser_click,mcp__playwright__browser_close`
   Add any other `browser_*` names the step needs.
3. `browser_navigate` to the page under test.
   Cookies, localStorage **and** sessionStorage are already injected by this point (§5) via `--init-script` — make no manual storage calls even though `browser_sessionstorage_set` and friends exist under `--caps=storage` (§7); this server's `.mcp.json` does not enable that capability, and hand-setting storage mid-session would fight the init-script injection.
4. **Confirm you are authenticated before trusting anything on the page.** The snapshot must show signed-in UI. If it shows a login page, stop per §3 — do not proceed and do not read locators off it.
5. `browser_snapshot` to read the real refs, roles, and accessible names. Perform the interaction the step describes, then snapshot again to confirm the resulting title, URL, or visible state matches what you intend to assert.
6. `browser_close`.
7. Write the step using **only** values confirmed in steps 3–6.
8. Report and hand off (§2): state which values you confirmed by snapshot and what remains unverified, then ask the user to run the scenario. Do not run it yourself, and claim no result you have not seen (N5).

## 5. Session state — how the three pieces flow

**Applies when:** touching [session-state.js](session-state.js), [global-setup.js](global-setup.js), `.auth/session.json`, or the `"I inject session state from file"` step.

`global-setup.js` runs once per test run, before any worker, and writes **two** artifacts from a single capture — together, so they cannot drift apart:

- `.auth/session.json` — native `storageState` (`cookies`, `origins[].localStorage`) plus a top-level `sessionStorage` field, since `context.storageState()` doesn't capture it. Playwright ignores unknown keys, so the extra field is harmless.
- `.auth/session.init.js` — localStorage + sessionStorage inlined as a web-storage init script.

Both consumers go through `readSessionState()` (in [session-state.js](session-state.js)), which **throws** on a missing, unparseable, or non-native file rather than injecting nothing:

| Consumer | cookies | localStorage | sessionStorage |
|---|---|---|---|
| `npx playwright test` (`Given "I inject session state from file"`) | `addCookies` | `addInitScript`, per origin | `addInitScript` |
| Playwright MCP (`.mcp.json`, §7) | `--storage-state` | `--storage-state` + `--init-script` | `--init-script` |

**Required shape of `session.json`.** `origins` is a plural **array**; each `localStorage` is an **array of `{ name, value }`**, not an object. Non-negotiable — it is Playwright's own format, handed straight to `browser.newContext({ storageState })`:

```json
{
  "cookies": [ { "name": "…", "value": "…", "domain": "…", "path": "/" } ],
  "origins": [ { "origin": "https://example.com",
                 "localStorage": [ { "name": "k", "value": "v" } ] } ],
  "sessionStorage": { "k": "v" }
}
```

**Why sessionStorage needs the init-script workaround:**

- Playwright's docs are explicit that it "does not provide API to persist session storage" — `storageState` covers only cookies, localStorage, IndexedDB (opt-in), and passkeys.
- This repo hand-rolls the documented workaround on both sides: `page.addInitScript()` for the test step, the generated init script for MCP.
- `--caps=storage` tools exist (`browser_sessionstorage_*` etc., §7) but are **not enabled** in this repo's `.mcp.json` — `--init-script` is the mechanism actually used to seed sessionStorage automatically on every page load, without an extra tool call per session.

**Other facts that matter:**

- **Reuse is conditional on validity, not existence** — setup regenerates if `session.json` is malformed *or* `session.init.js` is missing, so a half-built session is never trusted into a run.
- The login body is still a `TODO` stub in `global-setup.js`. Real credentials go there.
- An expired-but-valid session is **not** auto-refreshed — the file has to be deleted to force a fresh login.
- **IndexedDB is not captured** (that needs `storageState({ indexedDB: true })`, which this repo doesn't call). If the app keeps its auth token in IndexedDB, the session is incomplete despite looking valid.
- `session.init.js` contains **real session values as plaintext JavaScript**. `.auth/` is gitignored — keep it that way, and never paste its contents into logs, issues, commits, or chat.
- **Invariant:** both consumers must end up with all three pieces of state. If you change what `global-setup.js` writes, update `validateSessionState()`, `writeInitScript()`, and both readers in the same change.

## 6. Conventions to follow

**Applies when:** writing or editing any step definition — same scope as §4.

Match the existing style in [steps/test.steps.js](steps/test.steps.js).

- **Role-first locators.** Prefer `getByRole` / `getByLabel` / `getByText` over CSS or XPath.
  ✅ `page.getByRole('link', { name: 'Docs' })` ❌ `page.locator('.nav > a.docs-link')`
- **Scope before you assert.** Narrow to a container, then query inside it.
  ✅ `page.getByRole('navigation', { name: 'Docs sidebar' }).getByRole('link', { name })`
- **Parameterize with `{string}`** so one step serves many scenarios.
  ✅ `When("I click link {string}", async ({ page }, str) => …)` ❌ `When("I click the Docs link", …)`
- **Web-first assertions only.** `await expect(locator).toBeVisible()`, `toHaveTitle`, `toHaveURL`.
  ❌ `waitForTimeout`, `setTimeout`, or any manual sleep.
- **ESM imports** (`import … from`); Node builtins as `node:fs` / `node:path`.
- **Keep step text declarative and reusable** — specifics belong in the feature file, not the step name.

## 7. Reference — `.mcp.json`

```json
{
  "mcpServers": {
    "playwright": {
      "type": "stdio",
      "command": "npx",
      "args": [
        "@playwright/mcp@latest",
        "--isolated",
        "--storage-state=.auth/session.json",
        "--init-script=.auth/session.init.js"
      ],
      "env": {}
    }
  }
}
```

| Flag | Effect |
|---|---|
| `--storage-state=.auth/session.json` | Seeds cookies + localStorage (not sessionStorage). Silent no-op if missing or non-native → §3. |
| `--init-script=.auth/session.init.js` | Evaluated before every page's own scripts; carries localStorage + sessionStorage, closing the gap `--storage-state` leaves. |
| `--isolated` | Fresh in-memory profile per session, seeded by `--storage-state`, discarded on close. Documented pairing for `--storage-state`. |

⚠️ Do **not** add `--caps=storage`. It *is* a valid, documented capability (verified against `@playwright/mcp@latest`, v0.0.79) — it adds `browser_cookie_*`, `browser_localstorage_*`, `browser_sessionstorage_*`, and `browser_storage_state`/`browser_set_storage_state` tools. The reason to leave it off here is different from "it doesn't work": this repo's flow (§5) needs sessionStorage seeded automatically, on every page, before any step runs — which is what `--init-script` already does. Enabling `--caps=storage` on top would just add manual get/set tools that could be called out of step with, or instead of, the automatic injection, reintroducing the drift `global-setup.js` is designed to prevent (§5). If a step definition ever needs ad-hoc storage inspection, prefer `browser_evaluate` over adding this capability.

## 8. Failure modes — recognize and fix

| Symptom | Likely cause | Fix |
|---|---|---|
| MCP browser shows a login page | `.auth/session.json` missing, expired, or not in native shape | §3 — stop; have the user delete the file and re-run global setup |
| Cookies restore but localStorage doesn't | File has singular `origin` / object-shaped `localStorage`; Playwright ignores both | §5 — regenerate via global setup |
| App loads but behaves as anonymous | `.auth/session.init.js` missing or stale, so web storage never landed | §3 — stop; have the user re-run global setup |
| `Tool not found: mcp__playwright__…` | Schemas never fetched — or the tool isn't exposed because `--caps=storage` isn't enabled in `.mcp.json` (e.g. `browser_sessionstorage_set`, §7) | §4 step 2 — call `ToolSearch` for core tools; a missing storage/network/vision/pdf/devtools/testing/config tool means the capability flag would need to be added, which this repo intentionally doesn't do |
| Feature file edits have no effect | Stale `.features-gen/` — specs regenerate only when the user runs the suite | Ask the user to re-run; never edit `.features-gen/` to compensate |
| Step passes in MCP, fails in the run | Verified while logged out, or the scenario is missing the session-injection `Given` | Re-verify per §4; confirm the scenario injects session state |
| Flaky visibility assertion | Ambiguous locator matching several nodes | Scope to a container; add `exact: true`; avoid blind `.first()` |
